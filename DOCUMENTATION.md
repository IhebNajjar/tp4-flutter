## 1. Overview & Objectives

The goal of **Workshop 4 (TP4)** is to transform a local Flutter queue application into a cloud-backed, distributed real-time system using **Supabase** as the Backend-as-a-Service (BaaS).

### Key Objectives:
1. Connect Flutter to a cloud PostgreSQL database without a custom backend server.
2. Replace ephemeral in-memory state with real-time database synchronization.
3. Broadcast changes across multiple client devices using Supabase Realtime WebSockets.
4. Secure database operations using PostgreSQL Row Level Security (RLS) policies.
5. Apply Test-Driven Development (TDD) with unit, mock, and widget tests.

---

## 2. Technical Architecture

```
Flutter Client (Device 1) <───┐
                              ├───> Supabase Realtime (WebSockets) <───> PostgreSQL Database
Flutter Client (Device 2) <───┘
```

- **Database Layer**: PostgreSQL hosted on Supabase, storing records in the `clients` table.
- **Realtime Engine**: PostgreSQL replication publications (`supabase_realtime`) streaming change events via WebSockets.
- **State Management**: `QueueProvider` (extending `ChangeNotifier`) listening to change streams and exposing reactive state to Flutter widgets.
- **Presentation Layer**: `WaitingRoomScreen` using `Consumer<QueueProvider>` to render dynamic queue cards and control buttons.

## 3. Function & Class Details

### A. Data Model (`lib/models/client.dart`)

| Method / Property | Description |
| :--- | :--- |
| `String id` | Unique identifier (UUID generated by PostgreSQL `gen_random_uuid()`). |
| `String name` | Name of the waiting person. |
| `DateTime createdAt` | Timestamp used for First-In, First-Out (FIFO) queue ordering. |
| `Client(...)` | Constructor initializing all required fields. |
| `Client.fromMap(map)` | Factory parsing JSON maps from Supabase with safe timestamp handling. |
| `toMap()` | Serializes client data into a JSON map for database operations. |
| `toString()` | Returns formatted string representation for logging and debugging. |

### B. State Management (`lib/queue_provider.dart`)

| Method / Property | Description |
| :--- | :--- |
| `List<Client> get clients` | Returns unmodifiable list of clients for UI rendering. |
| `QueueProvider()` | Default constructor that initiates initial fetch and starts Realtime subscription. |
| `QueueProvider.forTesting(client)` | Testing constructor allowing dependency injection of a mock Supabase client. |
| `_fetchInitialClients()` | Reads all current queue tickets ordered by `created_at ASC`. |
| `_setupRealtimeSubscription()` | Connects to `supabase.channel('public:clients')` and updates local list on `INSERT` and `DELETE`. |
| `addClient(String name)` | Inserts a new record into the Supabase database. |
| `removeClient(String id)` | Deletes a ticket by UUID from the database. |
| `nextClient()` | Dequeues the first client in line according to FIFO order. |
| `dispose()` | Unsubscribes from WebSocket channels on provider disposal. |

### C. Presentation Layer (`lib/main.dart`)

| Component | Description |
| :--- | :--- |
| `void main()` | Initializes Flutter bindings, loads `.env`, initializes Supabase, and runs `WaitingRoomApp`. |
| `WaitingRoomApp` | Top-level `StatelessWidget` configuring `MaterialApp` and theme. |
| `WaitingRoomScreen` | Main screen with text input, `Consumer<QueueProvider>` list, and action buttons. |

## 4. Database Setup & Security (RLS)

### Table Schema
```sql
CREATE TABLE IF NOT EXISTS public.clients (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### Row Level Security (RLS) Policies
```sql
ALTER TABLE public.clients ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Allow public select" ON public.clients FOR SELECT TO anon USING (true);
CREATE POLICY "Allow public insert" ON public.clients FOR INSERT TO anon WITH CHECK (true);
CREATE POLICY "Allow public delete" ON public.clients FOR DELETE TO anon USING (true);

ALTER PUBLICATION supabase_realtime ADD TABLE public.clients;
```
